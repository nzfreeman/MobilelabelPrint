# 운영 설치 검토

## 설치할 내용

- 서버: `192.9.188.221`, 기존 Odoo 19 Docker 컨테이너.
- 운영 DB: `nzqb-odoo`.
- 새 모듈: `nzqb_label_print` 19.0.1.0.0. 기존 Android 앱과 ZPL용 Godex 모듈은 유지.
- 작업 전 PostgreSQL 백업을 서버의 새 전용 폴더에 생성하고 복원 가능한 형식인지 검사.
- 라벨·배치·문구·프린터·인쇄 요청/이력 테이블과 메뉴 추가. 기존 Odoo 시스템 관리자에게 라벨 관리자 권한을 연결.
- 인쇄 연결 전용 계정 생성. 일반 내부 사용자 권한 없이 지정된 프린터의 요청을 받거나 결과를 보고하는 권한만 부여.
- 이 계정용 API 키 1개 발급, 유효기간 1년. 서버에는 Odoo의 기존 해시 저장 방식을 사용하고, 원문은 PC 설정 파일로 전달하여 현재 Windows 사용자와 SYSTEM만 읽을 수 있게 제한.
- 현재 PC에서 연결 프로그램을 실행하고 Windows 로그인 시 자동 시작되도록 작업 스케줄러 등록. PC/프린터/인터넷이 연결되어 있어야 출력.
- PC에서 접속하는 프린터는 `192.168.68.55:9100`으로 제한. PC의 수신 포트나 프린터 DMZ는 열지 않음.

## 운영상 영향

모듈 설치 시 Odoo가 새 구조와 권한을 읽기 위해 잠깐 다시 로드될 수 있다. API 키가 저장된 PC가 침해되면 해당 프린터의 인쇄 데이터와 결과 보고가 영향을 받을 수 있으므로 전용 권한과 파일 접근 제한을 사용한다. 실제 시험 인쇄는 라벨 영역을 확인한 뒤 별도로 진행한다.

모듈/연결 프로그램과 테스트는 준비되었으나 운영 설치 및 계정·키 발급은 명시적 승인 전까지 실행하지 않는다.
