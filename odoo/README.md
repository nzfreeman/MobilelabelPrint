# Odoo 19 작업장 라벨 인쇄

`addons/nzqb_label_print`는 기존 ZPL용 `godex_label_printer`와 별도로 설치하는 EZPL 모듈입니다. Android 앱의 수동 mm 영역·회전·위치 보정과 같은 좌표 체계를 사용합니다.

## 사용 방법

1. Odoo의 **라벨 인쇄 → 등록 라벨**에서 라벨을 등록합니다. 사진은 구분용이며 출력되지 않습니다.
2. 글자가 똑바로 보이는 방향으로 가로·세로를 입력하고, 먼저 나오는 변·거꾸로 인쇄·위치 보정을 정합니다. 보정은 출력 미리보기 기준 오른쪽·아래가 양수입니다.
3. 영역마다 mm 위치와 크기, 내용을 입력합니다. `{BATCH}`, `{BB}`, `{MFG}`, `{PRODUCT}`, `{WEIGHT}`, `{QTY}`, `{STORAGE}`, `{RMP}`, `{ORIGIN}`, `{COMPANY}`를 사용할 수 있습니다. 빈 항목이 포함된 줄은 빠집니다.
4. **저장한 배치**에 배치번호와 제조일·Best Before(MGO/UMF)를 저장합니다. Odoo 로트를 선택해 연결할 수도 있습니다. 배치와 인쇄 이력은 삭제할 수 없습니다.
5. **미리 써 둔 문구**에 제품명·무게·수량·보관방법·RMP·원산지·회사명을 등록합니다.
6. **새 인쇄 요청**에서 라벨·프린터·배치·매수와 머리말을 선택하고 미리보기를 확인합니다. 무지 라벨 문구는 저장된 문구를 고르거나 직접 입력하고, 빼려면 값을 비웁니다.
7. **인쇄 요청**을 누르면 작업장 PC가 요청을 받아 출력합니다. 외부 이동통신망에서도 같은 방식으로 사용할 수 있습니다.

## 인쇄 연결 프로그램

Python 3.10 이상이면 별도 패키지가 필요 없습니다. `agent/config.example.json`을 `config.json`으로 복사하고, **연결 프로그램 전용 Odoo 계정과 API 키**를 설정합니다. 계정에는 `라벨 연결 프로그램 (전용 계정)` 권한만 주고 프린터의 연결 프로그램 계정에 지정합니다. 일반 관리자 비밀번호를 사용하지 마세요.

```powershell
python nzqb_print_agent.py --config config.json --heartbeat-only
python nzqb_print_agent.py --config config.json
```

Windows 자동 실행은 `agent/install.ps1 -PythonPath <python.exe 전체 경로>`로 등록합니다. 현재 Windows 사용자로 로그인되어 있어야 실행되며 Odoo 브라우저를 열어 둘 필요는 없습니다. PC의 절전 상태에서는 출력되지 않습니다. 계정 키는 `config.json`에 보관되므로 공유하거나 Git에 올리지 마세요.

연결 프로그램은 Odoo의 HTTPS에만 접속합니다. PC로 들어오는 서버나 포트는 열지 않습니다. 프린터 DMZ·외부 포트포워딩·공유기 VPN은 필요하지 않습니다. 프린터 주소는 설정의 허용 목록과 일치해야 합니다.

## 기록과 중복 출력 방지

- 매수는 EZPL `^P`에 한 번만 넣습니다. PC에서 매수만큼 데이터를 반복 전송하지 않습니다.
- 요청 접수 시 라벨 설정·문구·매수를 스냅샷으로 고정합니다. 나중에 라벨 설정을 바꿔도 대기 중인 요청은 바뀌지 않습니다.
- 서버는 DB 잠금으로 요청을 한 연결 프로그램에만 할당합니다. 처리 중 요청은 자동으로 다시 대기열에 넣지 않습니다.
- PC는 전송을 시작하기 전에 SQLite 기록을 디스크에 남깁니다. 전송 후 Odoo에 결과를 알리는 통신이 실패하면 **결과 보고만 다시 전송**하고 라벨은 다시 보내지 않습니다.
- 전송 중 PC 종료·연결 오류는 **출력 여부 확인 필요**입니다. 실제 라벨을 확인하고 필요한 경우 사유를 적어 **새 재인쇄 요청**을 만드세요. 물리적 출력과 DB 기록을 하나의 거래로 묶을 수 없으므로 정확히 한 번 출력됐다는 보장은 하지 않습니다.
- 기본 30분 넘게 대기한 요청은 확인 대기로 전환합니다. 확인 후 지금 출력하도록 승인하거나 취소할 수 있습니다.
- **프린터로 전송 완료**는 실제로 나온 라벨 매수 확인과 다릅니다. 전송 완료 매수 합계를 실물 생산 매수로 사용하지 마세요.
- `agent/state/agent.log`에 연결 기록, `journal.sqlite3`에 전송 시도 기록이 남습니다. 기록 파일을 삭제하고 미확인 요청을 재처리하면 중복 출력 위험이 있으므로 보존하세요.

## 서버 설치 및 검증

Odoo 19 CE, `stock`, `product_expiry`, `mail`, Pillow가 필요합니다. Barlow Semi Condensed 글꼴과 OFL 라이선스가 모듈에 포함됩니다. 먼저 별도 임시 DB에서 설치와 권한·대기열 테스트를 통과시킨 뒤 운영 DB에 설치합니다. 기존 Godex 모듈과 그 인쇄 이력은 변경하지 않습니다.
